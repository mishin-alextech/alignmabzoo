# Исследование локального V(D)J-анализа для AlignmentViewer

Дата проверки: 13 сентября 2026 года. Этап F2 из `alignment_agents.md`.
Документ совмещает согласованный контракт и текущее состояние реализации.
Вычислительные тесты и отправка пользовательских последовательностей не
выполнялись.

## 1. Вывод и границы

Рекомендуемый инструмент — локальный NCBI IgBLAST (`igblastn`). Белкового результата недостаточно: `igblastp` ищет V, но не D и J. Поэтому существующий ANARCI остаётся источником нумерации белков, а новый анализ потребует сохранения соответствующей ДНК. [Примеры NCBI](https://ncbi.github.io/igblast/cook/examples.html)

IMGT/V-QUEST работает с нуклеотидными последовательностями и предоставляет существенно больше функций, чем простое назначение V/D/J. Первую реализацию следует называть «V(D)J-анализ», не обещая тождественности результатов или полноты V-QUEST. Первая панель показывает назначения сегментов, качество совпадений и junction/CDR3; отличия от germline добавляются после проверки координат. [Руководство IMGT](https://www.imgt.org/IMGT_vquest/user_guide)

Для первой реализации входом IgBLAST служит сохранённое `nucleotide_sequence`: по решению пользователя оно уже содержит последовательность вариабельного домена. Проверка соответствия этой ДНК сохранённому белку — дополнительное улучшение после тестов, а не блокер реализации. Точный вид организма и подготовка совместимых баз с аннотациями остаются обязательными.

## 2. Что обнаружено в репозитории

- `backend/app/services/parser.py`: `ParseResult` хранит путь, имя, белок и `nucleotide_sequence` выбранного кандидата. Нуклеотиды передаются в `sequence_manifest.json` и `parsed_chains_nucleotide.txt`; feature, record и координаты выбранного кандидата не сохраняются.
- Парсер сначала использует qualifier `translation`; соответствие этой аннотации реальной ДНК не проверяется. Fallback GenBank использует `feature.extract`, SnapGene — сегменты и reverse complement. Учитывается `codon_start`; хвост неполного кодона отбрасывается, трансляция обрывается на первом stop. Отдельного чтения `transl_table` сейчас нет.
- Кандидаты выбираются по длине, при равенстве сохраняется первый. Текущее значение `MIN_PROTEIN_LENGTH` — 80. Исследование не меняет этот порог и не разрешает менять правила выбора белка.
- Для V(D)J-контракта `Hs` зафиксирован как китайский хомяк, а `Cm` — как бактриан. Маппинг ANARCI `Cm → alpaca` не используется для выбора базы IgBLAST.
- Нуклеотидные данные есть у новых job, включая derived job. Нумерация схемы и индексы MSA не заменяют координаты CDS; это ограничивает только будущую проекцию результата IgBLAST в колонки MSA, но не запуск IgBLAST по сохранённой ДНК.

## 4. IgBLAST, вспомогательные файлы и поставка

Документация NCBI описывает встроенную поддержку human, mouse, rat, rabbit и rhesus_monkey. Следовательно, для Hu/Ms/Rt/Rb предусмотрены встроенные организмы; Pg/Hs/Ov/Gt/Cm/Bv требуют собственной конфигурации. Она включает аннотации V (`.ndm.imgt`) и внутреннюю V-базу; для CDR3/FWR4 нужна совместимая J-аннотация `.aux`. Имена и последовательности J должны соответствовать выбранной поисковой базе. Для AIRR `d_frame` нужны дополнительные определения рамки D; готовый пример описан для мыши. [Установка и custom organism](https://ncbi.github.io/igblast/cook/How-to-set-up.html)

Linux-сборки включают `makeblastdb`; IMGT FASTA подготавливают через `edit_imgt_file.pl`, затем индексируют с `-parse_seqids -dbtype nucl`. Рабочие внутренние данные задаются через `IGDATA`. V, D и J поисковые базы задаются отдельно. Документация предупреждает о возможных патчах аннотаций между релизами. [Порядок подготовки NCBI](https://ncbi.github.io/igblast/cook/How-to-set-up.html)

Официальный каталог `LATEST` проверен 13.09.2026 и указывает на IgBLAST **1.22.0**. Зафиксированный Linux-архив содержит `internal_data`, видовые `.ndm.imgt` и `.aux` для human, mouse, rabbit и rat. Совместимость итогового образа и биологический контроль результатов проверяются после серверной сборки. [Release notes NCBI](https://ncbi.github.io/igblast/rel/Release-notes.html)

Контракт будущей поставки:

- До изменения Docker выбрать конкретный Linux-архив под архитектуру сервера и закрепить версию, URL и SHA-256. Проверить зависимости бинарников в Python 3.12-образе; не предполагать наличие IgBLAST на хосте.
- Создать манифест каждого набора: таксон, локус, источник, версия/дата, хеши FASTA и индексов, версии утилит подготовки, аннотации V/J, лицензия. Не обновлять базу автоматически при запуске job.
- Поместить неизменяемые программы и базы в образ. Вход, временные файлы и результаты анализа хранить только в каталоге UUID job. Не использовать `-remote` и внешние анализаторы.
- Не устанавливать новый Python-фреймворк. TSV достаточно читать стандартным `csv`; отдельную библиотеку AIRR добавлять лишь при необходимости проверки формата. Для IMGT-скрипта подготовки нужен Perl; при подготовке вне runtime он не требуется в рабочем слое.

## 5. Условия использования

NCBI описывает основную часть IgBLAST как работу правительства США без ограничений использования/воспроизведения, оговаривая сторонние файлы. Проверить notices конкретного архива и сохранить их в образе. Эта формулировка сама по себе не лицензирует внешнюю базу. [Copyright IgBLAST](https://ncbi.github.io/igblast/dev/copyright.html)

Актуальная страница IMGT указывает **CC BY 4.0 для данных и метаданных**, отдельно регулируя использование инструментов. Не переносить старые предположения об ограничениях данных на текущую версию. В манифесте сохранить атрибуцию, ссылку на лицензию и описание преобразования FASTA/индексации. Условия получения архивов и bot policy соблюдать отдельно; обход ограничений доступа не входит в план. [Условия IMGT](https://www.imgt.org/about/termsofuse.php)

Информация OGRDB опубликована под **CC0**; лицензия исходного кода сайта отдельная. Сохранить происхождение и рекомендуемое цитирование набора, даже при свободном распространении данных. [Лицензирование OGRDB](https://ogrdb.airr-community.org/render_page/licensing_statement.html)

## 6. Вход и координаты

Для первой реализации IgBLAST получает `nucleotide_sequence` из manifest
напрямую, без проверки обратной трансляцией. Этот путь согласован как рабочая
гипотеза до практических тестов. Если тесты покажут несовпадение входа и белка,
ниже описанная расширенная проверка становится обязательной.

Следующее — дополнительные улучшения происхождения и координат, не блокирующие
первый выпуск V(D)J-назначений.

1. Вместо потока голых белковых строк внутри парсера вести кандидата с белком, нуклеотидами, record/feature ID, упорядоченными сегментами, strand, `codon_start`, таблицей трансляции и источником белка (`translation` или вычисление). Возвращать выбранного кандидата по прежнему правилу длины; не выбирать другую CDS специально ради успешного IgBLAST.
2. Извлекать ДНК выбранной feature в кодирующем направлении. Для compound location, круговой записи и отрицательной цепи хранить отображение каждого кодона на координаты исходной записи. Одного интервала start/end для составной CDS недостаточно.
3. Сохранить полную ДНК выбранной CDS и отдельно диапазон выбранного домена в белке. Проверить, что её трансляция соответствует белку с учётом зафиксированной обработки terminal stop. Несовпадение qualifier и ДНК, неоднозначная локализация, frameshift или недоказанная рамка дают отсутствие проверенной связи, а не молчаливую подмену входа.
4. Для доменного диапазона `[a,b)` в проверенной трансляции отображение на ориентированную CDS: `[offset+3a, offset+3b)`, где `offset=codon_start-1`. Применять формулу только при непрерывном соответствии кодонов. Не отрезать J/FR4 по последнему пронумерованному остатку ANARCI без проверки полноты домена. Для неполного/неоднозначного домена показывать ограничение.
5. Хранить доменную нуклеотидную последовательность без MSA-gap и стабильный ID строки, хеш белка/ДНК, хеш исходного файла и версию парсера. Не восстанавливать ДНК обратной трансляцией белка. Снимок извлечённых данных писать в job, не в data-root.
6. Старым job показывать «Нуклеотидные данные не сохранены». Восстановление возможно отдельной явной операцией при наличии исходного файла и проверке тождественности выбранного белка; невозможность подтвердить исходный снимок отражать в происхождении. Старые результаты не перезаписывать.

ANARCI CSV, белковая MSA и V(D)J имеют разные координатные пространства.
Проекция `query IgBLAST → CDS → белок → колонка MSA` нужна только для будущей
подсветки назначений и различий от germline прямо в AlignmentViewer. Она не
нужна, чтобы показать назначения V/D/J, метрики и junction/CDR3, поэтому
отложена до результатов первого тестового запуска.

## 7. Результат, панель и интеграция

AIRR Rearrangement — TSV с заголовком; поля допускают отсутствие значения. В нём представлены назначения, локус, junction, координаты и сведения о выравнивании. Сохранять исходный TSV, разбирать поля по заголовкам и отличать отсутствующее значение от `false` и нуля. Выход конкретной версии IgBLAST сверить с зафиксированной версией AIRR, а не заявлять поддержку всех полей стандарта. [AIRR Rearrangement](https://docs.airr-community.org/en/stable/datarep/rearrangements.html)

Минимальный предлагаемый интерфейс:

- Фоновая операция анализа выбранных стабильных ID с профилем базы; результат связан с исходной job и хешами входа, сохраняется отдельно. Конкретные маршруты определить вместе с существующим механизмом производных job этапа D; не вводить независимую очередь сверх общего лимита.
- Внутренняя запись: `sequence_id`, состояние доступности и русская причина, `organism`, `locus`, версии инструмента/базы, список альтернатив `v_call`/`d_call`/`j_call`, метрики и junction nt/aa. Не сводить равнозначные назначения к одному имени.
- Под viewer панель выбранной строки. Для IGH/VHH показывать V/D/J; для IGK/IGL — V/J, D обозначать «Не применяется». Неопределённый D тяжёлой цепи обозначать «Не определён». Несоответствие локуса типу строки выводить диагностикой, без автоматической перегруппировки MSA.
- Качество: идентичность, длина совпадения/покрытие и предоставляемые инструментом score/support. E-value и идентичность не превращать в вероятность правильного назначения.
- Показывать junction/CDR3 с явной подписью источника и единицами nt/aa. Не перезаписывать CDR IMGT/Kabat/Chothia существующего viewer результатом IgBLAST.
- Проекцию координат и подробную таблицу отличий от germline отложить до тестов; первый UI не показывает их в координатах MSA.
- Сохранять `vdj/input.fasta`, `vdj/rearrangements.tsv`, `vdj/result.json`, `vdj/manifest.json` и диагностические выводы в каталоге производной job. Скачать исходный TSV и манифест. Исключение/перестановка строк не требует повторного анализа при неизменных ДНК и профиле базы.

Неполные, искусственные, гуманизированные и кодон-оптимизированные конструкции нельзя интерпретировать как прямое доказательство происхождения от найденного аллеля. Без сохранённой исходной природной ДНК синонимические отличия неотделимы от инженерного изменения. Близкие germline-аллели и короткий/изменённый D могут давать неоднозначность; UI обязан сохранять её. Неизвестный вид или отсутствующая база — отдельный статус доступности, без автоматического поиска по родственному виду.

## 8. Согласованные решения и приёмка

Для первой реализации зафиксированы решения:

1. `Hs` — китайский хомяк (*Cricetulus griseus*), `Cm` — бактриан (*Camelus bactrianus*).
2. Первый набор профилей — `Hu`, `Ms`, `Rb`, `Rt`. Остальные виды подключаются только после подготовки и проверки собственного профиля.
3. Единственный источник germline-баз — IMGT. OGRDB не используется в первом выпуске.
4. `nucleotide_sequence` новых job передаётся в IgBLAST напрямую. Проверка трансляции, координат feature и восстановление нуклеотидов старых job отложены как дополнительная работа после тестов.
5. Первый UI показывает назначения V/D/J, метрики и junction/CDR3. Проекции на MSA и подробные отличия от germline отложены.

После прямого разрешения пользователя проверки должны охватить: положительную/отрицательную и составную CDS, круговую запись, `codon_start` 1/2/3, несовпадение qualifier с ДНК, несколько одинаковых белков из разных features, неполный домен, stop/frameshift, неточную базу вида, VJ без D, неоднозначные назначения, отсутствующий `.aux`, старую job, codon-оптимизированную конструкцию, проекцию через вставки/gap и повторное MSA, отказ одного входа, перезапуск и общий лимит 2 job.

### 8.1. Контракт видового профиля

Видовой профиль нельзя считать доступным по строке в каталоге. Для каждого кода животного перед реализацией должен существовать отдельный манифест со статусом `ready`, `blocked` или `unavailable` и следующими полями:

- точный таксон, локус и правило выбора профиля для кода AlignMabZoo;
- версия и источник V/D/J FASTA, `.aux`, `.ndm.imgt`, `internal_data` и `optional_file`;
- SHA-256 каждого файла и дата получения;
- команда подготовки `makeblastdb`, версия IgBLAST и `IGDATA`;
- лицензии, атрибуция и ограничения распространения;
- контрольная последовательность с ожидаемым наличием или отсутствием V/D/J;
- причина статуса `blocked` или `unavailable`, если профиль не прошёл проверку.

Профиль `ready` означает не наличие опубликованной ссылки, а успешную локальную проверку подготовки базы, запуск `igblastn` без `-remote`, разбор результата и соответствие локуса. Для `Hs` и `Cm` вид уже определён, но профиль остаётся `blocked` до фактической подготовки IMGT-базы. Ближайший вид не выбирается автоматически.

### 8.2. Обязательный roadmap профилей всех животных

Реализованы встроенные профили `Hu`, `Ms`, `Rb`, `Rt`, подготовлены полные
custom-профили `Pg`, `Ov`, `Bv` и частичный K/L-профиль `Gt`. Поддержка всех
десяти кодов AlignMabZoo остаётся
обязательным продолжением F2. Для каждого
кода создаётся отдельный IMGT-профиль; использование базы другого животного
запрещено.

| Код | Видовой профиль | Плановый статус |
|---|---|---|
| `Ms` | *Mus musculus* | Первый выпуск |
| `Rb` | *Oryctolagus cuniculus* | Первый выпуск |
| `Rt` | *Rattus norvegicus* | Первый выпуск |
| `Pg` | *Sus scrofa* | Custom-профиль подготовлен; требуется контрольный запуск |
| `Hu` | *Homo sapiens* | Первый выпуск |
| `Hs` | *Cricetulus griseus* | Нет точного набора в релизе IMGT |
| `Ov` | *Ovis aries* | Custom-профиль подготовлен; требуется контрольный запуск |
| `Gt` | *Capra hircus* | Частичный custom-профиль K/L подготовлен; H недоступен |
| `Cm` | *Camelus bactrianus* | Нет точного набора в релизе IMGT |
| `Bv` | *Bos taurus* | Custom-профиль подготовлен; требуется контрольный запуск |

Каждый профиль обязан содержать собственные IMGT FASTA и индексы для `IGHV`,
`IGHD`, `IGHJ`, `IGKV`, `IGKJ`, `IGLV`, `IGLJ` в объёме, доступном для вида;
для лёгких цепей D не применяется. Вместе с ними фиксируются согласованные
`.aux`, `.ndm.imgt`, `internal_data`, `optional_file`, хеши, лицензия,
контрольные запросы и результат локального запуска. Отсутствующий сегмент или
неполная база фиксируются явно в профиле и UI, а не подменяются данными другого
вида.

### 8.3. Минимальный формат результата

До реализации нужно закрепить версию собственного `vdj/result.json`. Минимальная запись результата для одной последовательности должна содержать:

```text
sequence_id
status: ready | unavailable | failed | ambiguous
reason
profile_id
tool_version
v_calls[], d_calls[], j_calls[]
locus
query_coordinates
junction: {nt, aa}
metrics: {identity, alignment_length, coverage, score, evalue}
details: {
  query_length,
  significant_alignments,
  alignments
}
germline_differences[]  # отложено для первого UI
coordinate_projection   # отложено для первого UI
```

`details` формируется из второго локального запуска `igblastn -outfmt 3 -show_translation`; он сохраняет нуклеотидную и аминокислотную строки, координаты и символы различий относительно germline. Поля с отсутствующими данными сохраняются как `null` или пустой массив по единому правилу, а не смешиваются с `false` и нулём. Для лёгких цепей `d_calls` имеет статус «не применяется», для тяжёлых — «не определён» при неуспешном назначении. Исходные `rearrangements.tsv` и `igblast_report.txt` сохраняются рядом с JSON и остаются источниками для повторного разбора.

### 8.4. Дополнительные критерии готовности координат

Проекция считается проверенной только после совпадения на контрольных примерах всей цепочки `query IgBLAST → ориентированная CDS → кодоны → негэповой белок → колонка MSA`. Для положительной, отрицательной и составной CDS должны быть проверены рамка, reverse complement, границы feature и сохранение порядка кодонов. При смене MSA допускается изменение только последней проекции на колонку; V/D/J-назначения и белковые номера не должны сдвигаться.

Для каждого контрольного примера сохраняются входной хеш, профиль базы, исходный TSV, ожидаемый статус и результат проекции. Несовпадение qualifier с фактической трансляцией, frameshift, неполный домен или неоднозначная база переводят запись в `unavailable`/`ambiguous` с русской причиной и не дают публиковать частично выдуманные координаты. Это критерий технической корректности, а не биологическая валидация порогов назначения.

Готовность первой реализации подтверждается локальным воспроизводимым результатом на согласованных контрольных примерах с зафиксированными версиями баз и понятными состояниями недоступности. Проверка проекции добавляется отдельным критерием, когда появится её отображение в viewer. Настоящее исследование не заменяет такую проверку и не объявляет функцию биологически валидированной.

## 9. Фактическое состояние поставки IgBLAST (13.09.2026)

Для первого V(D)J-выпуска зафиксированы IgBLAST `1.22.0` для Linux x64 и
IMGT/V-QUEST reference directory release `202631-1` от 27 июля 2026 года.
Оба исходных архива и их SHA-256 находятся в build context. IMGT предоставляет
данные по CC BY 4.0; лицензия NCBI входит в архив IgBLAST.

Docker build проверяет исходные checksum, отдельно готовит профили
`hu`, `ms`, `rb`, `rt`, `pg`, `ov`, `gt`, `bv`, сохраняет исходные и очищенные V/D/J
FASTA и создаёт BLAST-индексы с `makeblastdb -parse_seqids`. Для первых четырёх
копируются встроенные видовые `.aux` и `.ndm.imgt`; для `pg`, `ov`, `bv` они
строятся из IMGT FASTA утилитами receptor-utils `0.0.67` и передаются IgBLAST
через `-custom_internal_data`. Затем Docker формирует и проверяет
`/opt/igblast/profiles/SHA256SUMS` и делает каталог read-only. Подробный
контракт приведён в [docker/igblast/README.md](../docker/igblast/README.md).

Восемь профилей считаются технически подготовленными для сборки.
Биологическое подтверждение остаётся отдельным этапом: после прямого указания
на запуск вычислительных проверок нужно выполнить контрольный V(D)J-анализ для
каждого вида и сопоставить locus, V/D/J и junction с ожидаемыми результатами.
`Gt` поддерживает только K/L; `Hs` и `Cm` заблокированы отсутствием точных
наборов в текущем IMGT-релизе. Они не заменяются базами близких видов.
