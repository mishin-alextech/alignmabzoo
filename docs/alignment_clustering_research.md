# Исследование кластеризации AlignmentViewer на MMseqs2

Дата: 6 сентября 2026 года. Этап F1 плана `alignment_agents.md`.

**Рекомендация:** использовать локальный MMseqs2 как основной инструмент определения кластеров, начать с `easy-cluster` для полных вариабельных доменов. Сохранить Clustal Omega для MSA и все исходные строки. Кластеризация CDR3 требует отдельной оценки чувствительности. Документ представляет исследование и предложения для согласования; реализация, установка и вычислительные проверки не выполнялись.

## 1. Основания и состояние проекта

Прочитаны `alignment_agents.md`, `backend/app/services/alignment.py` и `Dockerfile`. Сейчас Clustal обрабатывает пакеты `vheavy` (VHeavy вместе с VHH), `vkappa` и `vlambda`; порядок панелей включает также Other. Идентификатор Clustal формируется из имени, а контракт C вводит стабильные ID последовательностей. Интеграцию кластеризации следует строить после появления этих ID. Пакет Other сейчас не объявлен в `ALIGNMENT_BATCHES`; исследование не является разрешением менять эту политику.

Предлагаемое разделение: принадлежность к кластерам рассчитывать внутри типа цепи, а MSA оставить в существующих пакетах. Поэтому VHeavy и VHH можно сохранить в общем MSA, не объединяя их кластеры. Межвидовое ограничение не вводить автоматически: животное и проект остаются происхождением строки. Эти решения требуют подтверждения перед production-реализацией.

## 2. Проверенные свойства MMseqs2

### Режимы и ограничения гарантий

`easy-cluster` предоставляет каскадный workflow; `easy-linclust` использует Linclust. Каскад может сменить представителя так, что ранние участники перестанут удовлетворять критериям относительно него; `--cluster-reassign` предназначен для коррекции. Порог идентичности по умолчанию может использовать оценку по score; `--alignment-mode 3` вычисляет долю идентичных позиций. `--split-memory-limit` ограничивает основные структуры предфильтра, а не всю память процесса. Доступны Linux-сборки AVX2, SSE4.1, SSE2 и ARM64. [Руководство MMseqs2](https://github.com/soedinglab/MMseqs2/wiki)

Параметры релиза 18 допускают следующий выбор. [Определения параметров в исходном коде](https://raw.githubusercontent.com/soedinglab/MMseqs2/18-8cc5c/src/commons/Parameters.cpp)

| Параметр | Значение для проектирования |
|---|---|
| `--min-seq-id` | Порог идентичности, доля 0–1 |
| `--alignment-mode 3` | Явное вычисление идентичности |
| `--seq-id-mode 0` | Знаменатель — длина выравнивания; режимы 1/2 используют более короткую/длинную последовательность |
| `-c` | Минимальная доля покрытия |
| `--cov-mode 0` | Покрытие обеих последовательностей |
| `--cov-mode 1` / `2` | Покрытие target / query; асимметричные варианты |
| `--cluster-mode 0` | Greedy set cover |
| `--cluster-mode 1` | Компоненты связности |
| `--cluster-mode 2` | Greedy incremental, по длине |
| `-e` | Дополнительный порог E-value; его нельзя забывать при работе с короткими строками |
| `--threads 1` | Ограничение числа потоков |

У set cover центр выбирается по числу связей; incremental начинает с более длинных строк. Компоненты связности допускают транзитивные цепочки. При стандартном знаменателе точная идентичность учитывает внутренние gap-колонки; это локальное выравнивание, а не глобальная идентичность всего белка. Нативный cluster TSV содержит пары «представитель — участник». [Разделы о кластеризации и форматах](https://github.com/soedinglab/MMseqs2/wiki#clustering-modes)

**Вывод для UI:** надпись «кластер 90%» не означает, что каждая пара его участников имеет 90% идентичности. Например, два участника могут отличаться от центра в разных позициях и различаться между собой сильнее. Режим connected components ещё шире: связь A–B и B–C не обещает соответствия A–C. Ни один предложенный режим нельзя называть строгой попарной группой без отдельной проверки всех пар. Reassignment решает проблему конечного представителя, но не превращает группу в множество попарно подходящих последовательностей и не доказывает полноту поиска.

### Сравнение workflow

| Критерий | `easy-cluster` | `easy-linclust` |
|---|---|---|
| Предлагаемая роль | Первый кандидат для коллекций доменов AlignMabZoo | Альтернатива после оценки размера наборов и качества |
| Основной компромисс | Дополнительный поиск и каскад; больше работы | Линейное масштабирование Linclust, ограниченный поиск кандидатов |
| Риск для продукта | Параметры каскада и конечный представитель должны быть проверены | Отсутствие ребра нельзя трактовать как доказанное отсутствие сходства |
| Оценка результата | Число кластеров, доля одиночных строк, ошибки относительно контрольных пар | Те же показатели, плюс потери относительно easy-cluster |

Первичная публикация Linclust описывает выбор небольшого числа k-mer на последовательность и линейное масштабирование. Описанные настройки k=10/14 относятся к алгоритму публикации; их нельзя считать универсальным минимальным размером CDR3 или без проверки переносить в каждый релиз. Статья оценивает большие белковые базы и не валидирует наш сценарий коротких CDR3. [Steinegger и Söding, 2018](https://www.nature.com/articles/s41467-018-04964-5)

## 3. Область сравнения и предлагаемые эксперименты

### Полный домен — первый этап

Предлагается извлекать последовательность подтверждённого вариабельного домена без MSA-gap. Не следует молча называть «полным доменом» весь выбранный парсером белок: он может включать дополнительные участки. Перед включением режима нужно подтвердить, что хранимый белок соответствует домену, либо сохранять точные границы ANARCI и извлекать этот интервал. Если достоверных границ нет, строка получает причину «Не определены границы вариабельного домена», оставаясь в viewer и MSA.

Предлагаемая начальная конфигурация для обсуждения: `easy-cluster`, `--alignment-mode 3`, `--seq-id-mode 0`, `--cov-mode 0`, `--cluster-mode 0`, `--cluster-reassign 1`, `--threads 1`. Явно задавать режимы, чтобы смысл результата не зависел от автоматически выбранных сочетаний параметров.

Начальная исследовательская сетка: идентичность 0,80 / 0,90 / 0,95 и покрытие 0,80 / 0,90; кандидат первой пробы — 0,90 и 0,90. Это инженерные точки сравнения, **не валидированные пороги клональности или специфичности**. Порог E-value, sensitivity и настройки masking сохранять в метаданных; перед прогоном зафиксировать фактические значения `easy-cluster -h` выбранного релиза. Не ослаблять фильтры автоматически по результату «слишком много одиночных строк».

Поскольку сходство framework может доминировать в полном домене, соседство не интерпретировать как одинаковую антигенную специфичность. Кластеризация — способ сравнения последовательностей, а не доказательство общего клона.

### CDR3 — отдельная исследовательская ветка

Входом служит одна выбранная схема IMGT/Kabat/Chothia и её CDR3, восстановленный по индексам MSA с удалением gap. Схему фиксировать в результате. Отсутствующий или пустой CDR3 не подменять полным доменом; показывать строку вне кластеризации с причиной.

Из устройства k-mer-поиска следует риск: короткая строка предоставляет мало затравок, а совпадение высокого процента на коротком участке может не пройти остальные фильтры. Поэтому применять стандартный workflow без контрольной оценки нельзя. Особенно проверить короткие CDR3 лёгких цепей, близкие варианты с одной заменой, разную длину и вставки. Публикация Linclust не устанавливает безопасный порог длины для нашего приложения; точный предел сейчас неизвестен.

После разрешения на эксперимент сравнить результаты с исчерпывающим попарным выравниванием небольшого контрольного набора с заранее определённой метрикой. Биологический специалист должен разметить ожидаемые сходные и несходные пары. Оценить отдельно пропущенные связи предфильтра и связи, отвергнутые покрытием/E-value. Изменения k-mer, sensitivity, masking и E-value проводить по одному и сохранять параметры. Если приемлемая полнота не достигается, предложить отдельный точный метод для CDR3, сохранив MMseqs2 для доменов; не включать такой fallback молча.

## 4. Docker, ресурсы и воспроизводимость

На открытой странице релизов доступен **18-8cc5c**, commit с префиксом `8cc5ce3`; это кандидат закрепления для будущей интеграции. Он не установлен и не проверен внутри нашего контейнера. Для сборки из исходников этот релиз требует CMake ≥3.15 и <4. [Официальный релиз](https://github.com/soedinglab/MMseqs2/releases/tag/18-8cc5c)

Предлагается установить CPU-сборку в существующий Python 3.12 Docker-образ отдельным build-этапом. Закрепить тег, полный commit и SHA-256 скачанного архива в репозитории; не использовать `latest` или плавающий `master`. Выбрать артефакт после чтения архитектуры и CPU-флагов целевого Linux-сервера; AVX2 не предполагать по Windows-машине разработки. Если подходящий проверяемый бинарный архив недоступен, собрать тот же закреплённый исходник. Сохранить текст лицензии поставки. Новые Python/React-библиотеки, CUDA, GPU, Conda и внешний сервис для этой архитектуры не нужны.

Проверки будущей установки: внутри готового образа определить `mmseqs version`, доступность workflow и согласованность версии; затем только с прямым разрешением выполнить небольшой вычислительный пример. Отдельно проверить дочерние процессы easy-workflow и отсутствие записи вне job. Нельзя считать совместимость доказанной наличием скачиваемого архива.

Ресурсная политика предложения:

- Обычные, производные и кластеризационные job используют общий лимит двух запусков. Все пакеты внутри одной job последовательно запускают MMseqs2 и Clustal с одним потоком; при необходимости задаётся `OMP_NUM_THREADS=1` дочернему процессу.
- Рабочий каталог, временная база и `TMPDIR` находятся внутри `/app/jobs/<job_id>/clustering`. Общую временную базу разных job не использовать.
- Не устанавливать произвольное ограничение памяти контейнера: это противоречило бы действующим требованиям. Размер `--split-memory-limit` выбирать по доступной памяти сервера и результатам измерения двух одновременных job, оставляя запас приложению и ОС.
- Измерять время, peak RSS и максимальный объём временных файлов для типичного и максимального набора. Сейчас численные обещания времени/памяти/диска отсутствуют: объём данных и характеристики сервера не измерены.
- Перед запуском проверять свободный диск; порог резерва согласовать по измерениям. Нехватка диска и сбой процесса дают русскоязычную ошибку без замены текущего viewer.
- Сохранять итоговые TSV, параметры и журнал; временные базы удалять только внутри проверенного UUID-каталога после успешной публикации результата. Политику хранения диагностических временных файлов при ошибке согласовать до rollout.

## 5. Архитектура интеграции и артефакты

Предлагаемая цепочка: выбранные стабильные ID → извлечение области → MMseqs2 по типам цепей → нормализация таблицы кластеров → прежний MSA или новый Clustal по существующим пакетам → явный порядок строк viewer.

Все новые файлы производной job предлагается хранить так:

```text
clustering/
  manifest.json
  sequence_map.json
  clusters.json
  <chain_type>/
    input.fasta
    result_cluster.tsv
    result_rep_seq.fasta
    result_all_seqs.fasta
    tmp/
```

Названия выходных файлов следует подтвердить по закреплённому workflow при будущей проверке. Представитель используется как описание кластера; `result_rep_seq.fasta` никогда не заменяет полный вход Clustal.

Предлагаемое содержимое:

- `sequence_map.json`: короткий безопасный токен FASTA → стабильный ID → отображаемое имя, тип цепи, исходные координаты области. Не использовать имя как уникальный ключ, не отдавать клиенту абсолютные пути. Одинаковые белки с разными ID сохраняются отдельными участниками.
- `manifest.json`: версия формата, родительская job, выбранные ID, хеш входов, область и схема, режим workflow, все разрешённые параметры, точный argv, версия/хеш MMseqs2, время и итог. Команды и stderr/stdout также включать в append-only `log.txt`.
- `clusters.json`: ID кластера, ID представителя, полный список участников, тип цепи, порядок показа; отдельный список строк вне кластеризации с причинами. ID кластера стабильны внутри результата, но не обещают сохраняться при изменении набора или параметров.

Проверять каждый TSV-ID по отображению входа; запрещать неизвестные, потерянные и повторно назначенные ID. Одиночные кластеры и одинаковые последовательности сохранять. Нулевая подходящая область — понятный результат без вызова инструмента; одна подходящая строка — одиночный кластер. Не превращать потерянные инструментом записи автоматически в «биологически одиночные».

Новый API нужно проектировать поверх производных job этапа D: запрос содержит родительскую job, ID, область, разрешённые параметры и признак повторного MSA. Клиент не передаёт argv и пути. Точный endpoint и wire-формат закрепить в контракте реализации после выбора биологических параметров. История viewer хранит ссылки на готовые результаты и порядок; undo/redo не запускают MMseqs2 или Clustal.

## 6. Два пользовательских действия и координаты MSA

| Действие | Вычисления | Координаты |
|---|---|---|
| «Кластеризовать» | MMseqs2, затем перестановка имеющихся строк | `seq`, `numbering`, `cdr` не изменяются |
| «Кластеризовать и выровнять заново» | MMseqs2, затем Clustal со всеми оставшимися строками каждого прежнего пакета | Нумерация и CDR повторно проецируются в новое MSA |

В обеих ветках до успешного завершения сохранять прежнюю версию. Порядок вывода определять явно: панели в существующем порядке, внутри панели кластеры по убыванию размера и затем ID представителя; представитель первым, остальные по отображаемому имени и стабильному ID. Это предложение для согласования. Перестановка FASTA сама по себе не является контрактом порядка viewer. Скачивание должно соответствовать выбранному результату и явно зафиксированному порядку.

**Рекомендуемый вариант MSA:** одно выравнивание каждого существующего пакета, а кластеры задают блоки отображения. При одинаковом наборе новый запуск Clustal может воспроизвести старое MSA; данная архитектура не обещает улучшить выравнивание благодаря кластеризации.

**Независимый MSA каждого кластера:** допустим только как отдельная будущая функция. Колонка 20 разных кластеров больше не является общей координатой; нельзя просто склеить строки с padding и считать их единым сопоставимым MSA. Нужны отдельные панели и локальные частоты/экспорты либо последующее согласованное профильное выравнивание. Последний вариант — новый алгоритмический этап, требующий самостоятельной проверки качества; в первую реализацию не включать.

Guide tree Clustal определяет порядок прогрессивного выравнивания и может дать альтернативный порядок листьев. Документация Clustal различает guide tree и филогенетическое дерево. [EMBL-EBI](https://www.ebi.ac.uk/jdispatcher/docs/faqs/clustal/)

Для AlignMabZoo это подходящая отдельная команда «Упорядочить по дереву», но без определённого правила разрезания дерево не даёт требуемую таблицу кластеров и пороги идентичности. Оно не заменяет выбранный MMseqs2.

## 7. Решения до реализации и будущая приёмка

Оркестратору нужно согласовать:

1. Первая область: полный подтверждённый домен (рекомендация) или CDR3; для CDR3 — схема и правила выбора её пользователем.
2. Порог идентичности и покрытия: начать эксперимент с 0,90/0,90 и сравнительной сетки раздела 3 либо предоставить биологически обоснованные значения.
3. Семантика кластера: set cover с reassignment (рекомендация), incremental с длинным представителем или транзитивные компоненты; нужна ли строгая проверка всех пар.
4. Кластеризация отдельно VHeavy/VHH (рекомендация) или совместно; сохранять ли свободу межвидового сравнения в пределах типа цепи.
5. Роль кластеров: блоки в общем MSA пакета (рекомендация) или независимые MSA с отдельными координатами. Для общего MSA принять, что повторный запуск не гарантирует новых колонок.
6. Подтвердить предложенный порядок кластеров и участников, правила ручной перестановки после кластеризации.
7. Выделить контрольный набор и разрешить измерения; затем установить ресурсные резервы, время ожидания и сроки хранения временных файлов.

После прямого разрешения проверить: идентичные строки с разными ID; пустую/одиночную область; отсутствующие CDR; короткие CDR3 и вставки; разницу set cover/connected components; критерии относительно конечного представителя; повторяемость закреплённого запуска; сохранение всех строк MSA; правильность проекции CDR; экспорт и undo/redo; одновременные обычную и кластеризационную job; нехватку диска, сбой MMseqs2/Clustal и recovery. Сравнение с контрольными парами должно предшествовать заявлению о пригодности биологических порогов.

Исследование завершает F1, но не включает функцию кластеризации в приложение. Вычисления, тесты, установки и передача пользовательских последовательностей во внешние сервисы не выполнялись.
