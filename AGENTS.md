# AGENTS.md — операционная инструкция для разработки AlignMabZoo

## 1. Статус и приоритет требований

AlignMabZoo — самостоятельный Docker-сервис для обработки SnapGene `.dna` и GenBank `.gb` файлов с последовательностями моноклональных антител: извлечения белков, нумерации ANARCI, CDR-аннотации, мультивыравнивания Clustal Omega и интерактивного просмотра результатов.

Этот документ фиксирует согласованные решения и является **приоритетным** для разработки. `PROJECT_PLAN.md` пока сохраняется как исторический черновик; при расхождении с этим документом следовать `AGENTS.md`. Не дополнять требования догадками: неописанное значимое решение согласовывать с пользователем.

ИИ-агенты используются только при разработке. В самом приложении LLM-компонентов нет.

## 2. Роль оркестратора

Оркестратор разбивает разработку на изолированные задачи и делегирует производственный код субагентам. Перед запуском субагента он обязан сформулировать контракт:

- файлы, которые разрешено создать или изменить;
- входы, выходы и формат данных;
- ограничения и то, что менять нельзя;
- проверяемый критерий готовности.

После завершения задачи оркестратор проверяет контракт, соблюдение глобальных правил и импорт/сборку соответствующего модуля. Если результат не соответствует контракту, он возвращает задачу тому же субагенту с конкретными замечаниями. Тесты не запускаются без прямого указания пользователя.

## 3. Архитектура и развёртывание

### 3.1. Сервис

- Новый сервис, независимый от существующего портала и `mabseq-server`.
- Backend: Python 3.12, FastAPI, Uvicorn/Gunicorn ASGI worker, Pydantic, Biopython, autosnapgene, anyio/aiofiles.
- Frontend: React 18, TypeScript, MUI, Vite.
- Собранный фронтенд раздаёт FastAPI.
- Nginx публикует сервис отдельным поддоменом `alignmabzoo.<домен>` и проксирует его во внутреннюю Docker-сеть `internal-net`.
- Дополнительной авторизации нет.

### 3.2. Docker runtime

- Образ строится на Python 3.12.
- В образ устанавливаются `clustalo` и `hmmer` из APT.
- ANARCI поставляется в образе с закреплённой, проверенной HMM-базой, которая загружается во время `docker compose build`; не предполагать, что `ANARCI` установлен на хосте. После сборки обязательно проверить внутри контейнера доступность `ANARCI`, `hmmscan` и `clustalo`.
- При старте job проверять доступность `ANARCI`, `hmmscan` и `clustalo` и возвращать понятную русскоязычную ошибку при неисправном окружении.
- Контейнер ограничен `2 CPU`, ограничение памяти не задаётся.
- Максимум две параллельные job: общий семафор `MAX_CONCURRENT_JOBS=2`.
- Каждая job запускает Clustal Omega с одним потоком: `--threads 1`.

## 4. Общие правила реализации

- Идентификаторы кода — английские; комментарии, docstring, UI, логи, сообщения об ошибках и документация — русские.
- Ошибка одного входного файла не прерывает job. Она попадает в `report.json` и `log.txt`; итоговый статус такой job — `partial`.
- Статусы job: `queued → running → done | partial | failed`.
- При запуске приложения все сохранённые job в статусе `running`, прерванные перезапуском контейнера, переводятся в `failed` с причиной на русском языке.
- Каждая job изолирована UUID-каталогом; входные данные не копировать обратно в data-root.
- Не добавлять в приложение LLM, иной фреймворк или авторизацию без явного согласования пользователя.
- Не запускать тесты без прямого указания пользователя.

## 5. Формат job и артефакты

`/app/jobs/<job_id>/` содержит:

```text
jobs/<job_id>/
├── parsed_chains.txt
├── chains_named.fasta
├── log.txt
├── log_valid_error.txt
├── report.json
├── anarci/
├── alignment/
│   ├── input.fasta
│   └── alignment.aln
└── alignment.json
```

- `jobs_registry.json` находится в корне `/app/jobs` и хранит название job длиной до 200 символов, выбор пользователя, статусы, время и итоговые счётчики.
- `log.txt` — единый append-only лог job: число найденных файлов, ошибки, переименования, команды ANARCI/Clustal и их итоги.
- `log_valid_error.txt` содержит только ошибки определения ID/цепи.
- `report.json` содержит обработанные, пропущенные и ошибочные файлы с причиной.

## 6. Pipeline

Порядок этапов фиксирован:

```text
1. Парсинг .dna/.gb → parsed_chains.txt
2. ID naming → chains_named.fasta + log_valid_error.txt
3. ANARCI: IMGT, Kabat, Chothia → CSV
4. Clustal Omega → alignment/alignment.aln
5. CDR и numbering в координатах MSA → alignment.json
```

### 6.1. Discovery и парсинг

- Хардкодить неизменный маппинг десяти директорий животных: `Ms`, `Rb`, `Rt`, `Pg`, `Hu`, `Hs`, `Ov`, `Gt`, `Cm`, `Bv`.
- Проекты — папки первого уровня животного; группы — папки первого уровня проекта. Поиск `.dna`, `.gb` и `.genbank` внутри выбранных групп рекурсивный.
- `.dna`: autosnapgene, CDS `translation` либо fallback-трансляция Biopython с учётом `codon_start`, reverse complement и стоп-кодона.
- `.gb`/`.genbank`: Biopython `SeqIO` с аналогичной логикой.
- Из файла брать одну самую длинную белковую последовательность не короче 20 aa.
- В `parsed_chains.txt` использовать FASTA и путь вида `<проект>/<группа>/<имя>`; промежуточные уровни под группой опускать.

### 6.2. ID naming

- Нормализация строго case-sensitive.
- Имя проекта для извлечения клона — префикс до первого `-<цифра>`; при отсутствии такого суффикса использовать всё имя.
- Сначала искать точное имя проекта в имени файла, затем fallback по двум из трёх символов и fallback по двухбуквенному коду животного.
- Нормализация: `HC`, `VH`, `HeavyC`, `VHeavy` → `VHeavy`; `VK`, `VK1`, `V1K`, `K1C`, `KC`, `KC1`, `kappa1`, `Kappa`, `Kappa1`, `KappaC`, `VKappa` → `VKappa`; `LC`, `LC1`, `LC2`, `VLambda` → `VLambda`.
- Если цепь не определена, сохранить последовательность с группой `Other`, записать диагностическое сообщение в `log_valid_error.txt` и не исключать её из MSA.

### 6.3. ANARCI и CDR

- Для каждой последовательности выполнить три запуска `ANARCI` с `--scheme imgt`, `kabat`, `chothia`, `--csv` и `--outfile`; сохранять стандартное содержимое CSV в `anarci/` как `<имя>_<схема>.csv`.
- Последовательности считаются валидными подтверждёнными вариабельными доменами. Не строить обычный пользовательский сценарий отказа ANARCI, но защищённо логировать непредвиденный сбой и переводить job в `partial`.
- Указывать `--use_species` только если соответствующий germline есть в HMM-базе:

  | Код животного | ANARCI species |
  |---|---|
  | `Ms` | `mouse` |
  | `Rb` | `rabbit` |
  | `Rt` | `rat` |
  | `Pg` | `pig` |
  | `Hu` | `human` |
  | `Cm` | `alpaca` |
  | `Bv` | `cow` |
  | `Hs`, `Ov`, `Gt` | без `--use_species` |

- CDR не помечены отдельными полями в CSV. `cdr_extract` должен получать нумерацию из заголовков/строк CSV, применить стандартные границы IMGT/Kabat/Chothia с учётом типа цепи и перевести позиции в индексы строки `.aln`, включая вставки и gap.

### 6.4. MSA и JSON viewer

- Один `alignment.aln` на job. Входной FASTA сортировать блоками `VHeavy → VKappa → VLambda → Other`, внутри блока — по имени файла.
- `alignment.json` возвращает `groups` для этих групп. Каждая последовательность содержит `name`, выровненную `seq`, `numbering` для трёх схем и `cdr` с массивами индексов `cdr1`, `cdr2`, `cdr3`.
- В `numbering` gap соответствует `null`; CDR содержит координаты выровненной строки, а не номера схемы.

## 7. API и frontend

Backend предоставляет:

- `GET /api/health`;
- `GET /api/animals`, `GET /api/animals/{code}/projects`, `GET /api/projects/{...}/groups`;
- `POST /api/jobs`, `GET /api/jobs`, `GET /api/jobs/{id}`;
- `GET /api/jobs/{id}/alignments`, `GET /api/jobs/{id}/exclusions`;
- endpoints для лога, `report.json`, `.aln` и CSV-скачиваний.

Frontend включает:

- `JobWizard`: название до 200 символов, выбор животных, проектов и групп, включая «все группы» и «применить ко всем»;
- `JobStatus`: polling статуса и live-лога;
- страницу результатов с адаптированными `AlignmentViewer` и `AlignmentExclusions`, отчётом и скачиваниями;
- список job с названием, статусом, датой и числом последовательностей.

## 8. Этапы и контракты субагентов

1. **Каркас и deployment.** Dockerfile, Compose, Nginx-конфигурация, FastAPI health endpoint, Vite/React skeleton. Готово, когда контейнер видит read-only data-root, writable jobs-root и доступен в `internal-net`; после `docker compose build` внутри контейнера подтверждена доступность `ANARCI`, `hmmscan` и `clustalo`.
2. **Discovery.** Маппинг животных, mtime-кэш и browse API. Не изменять data-root.
3. **Парсинг и ID naming.** Модули извлечения белков и нормализации ID согласно разделу 6. Готово, когда формируются оба FASTA и диагностические логи.
4. **ANARCI, MSA и CDR.** Раннер с маппингом species, нативными CSV, ограничением потоков, `.aln` и CDR в координатах MSA.
5. **Жизненный цикл job и API.** Дисковый реестр, очередь максимум из двух запускающихся job, recovery после перезапуска, отчёты, скачивания и JSON viewer.
6. **Frontend.** Wizard, статус, результаты, список job; использовать существующие компоненты viewer как основу.
7. **Полировка и deployment review.** Русскоязычные ошибки, README, ревью read-only mount, CPU limits, Nginx и отсутствия несанкционированной записи в data-root.

Для каждой задачи субагенту передавать только относящийся к ней контекст, список файлов и критерий готовности. Не поручать субагентам изменение несвязанных модулей.
