# AlignMabZoo — журнал реализации

## 2026-09-05. Маппинг кода животного → имя директории (исправление бага «зависание при выборе животного»)

### Проблема
При выборе любого животного (например, `Rb` — кролик) веб-интерфейс зависал:
`GET /api/animals/Rb/projects` сканировал несуществующий каталог
`<data_root>/Rb`, а реальные данные лежат в каталогах с полным именем.

### Причина
`DiscoveryService` (и `validate_selection` в `job_pipeline.py`) строили путь как
`data_root / <двухбуквенный код>`, тогда как реальная структура данных:

```
/home/bioinfo/synced/data/mabzoo/
├── 1-2_Mouse mAbs_seq results/        → Ms
├── 3_Rabbit mAbs_seq results/        → Rb
├── 4-5_Rat mAbs_seq results/         → Rt
├── 6_Pig_mAbs_seq_results/           → Pg
├── 7_Human_mAbs_seq_results/         → Hu
├── 80_83_Hamster_mAbs_seq_results/   → Hs
├── 90_Ovis_Aries_mAbs_seq_results/   → Ov
├── 92_Goat_mAbs_seq_results/         → Gt
├── 94_95_Camelids_mAbs_seq_results/  → Cm
└── 96_97_Bovine_mAbs_seq_results/    → Bv
```

Имена директорий животных неизменны — маппинг имя→код хардкодится.

### Изменения

#### 1. `backend/app/services/discovery.py`
- Добавлен `ANIMAL_DIRECTORIES: Final[dict[str, str]]` — хардкодированный
  маппинг код животного → имя директории (10 записей из структуры данных).
- `ANIMAL_NAMES` сохранён без изменений (порядок и коды не изменились).
- Добавлен метод `animal_directory_name(animal_code) -> str` (ValueError для
  неизвестного кода).
- `list_projects`: путь каталога животного теперь
  `self._data_root / self.animal_directory_name(animal_code)`.
- `list_groups`: аналогично — `animal_directory = self._child_directory(
  self._data_root, self.animal_directory_name(animal_code))`.

#### 2. `backend/app/services/job_pipeline.py`
- `validate_selection`: путь каталога группы теперь
  `data_root / discovery.animal_directory_name(code) / project_name / group_name`
  (ранее `data_root / code / project_name / group_name`).

#### 3. `docker-compose.yml`
- Volume: `/home/bioinfo/synced_data/mabzoo:/synced_data/mabzoo:ro`
  (реальный путь данных на хосте — `/home/bioinfo/synced_data/mabzoo`).

#### 4. `backend/app/config.py`
- Значение по умолчанию `data_root`: `/synced_data/mabzoo` →
  `/home/bioinfo/synced_data/mabzoo` (совпадает с путём на хосте; в контейнере
  путь переопределяется `ALIGNMABZOO_DATA_ROOT=/synced_data/mabzoo`).

### Не изменено
- API-контракты (`/api/animals`, `/api/animals/{code}/projects`,
  `/api/animals/{code}/projects/{project}/groups`) — коды животных в URL
  остаются двухбуквенными.
- Фронтенд — без изменений.
- `naming.py`, `parser.py`, `anarci_runner.py`, `alignment.py`, `cdr_extract.py`,
  `job_registry.py` — без изменений.

### Тесты
Локальная проверка `DiscoveryService` на тестовой структуре данных: все 6 тестов
(список животных, проекты, группы, has_project, animal_directory_name,
неизвестный код) пройдены.

## 2026-09-05. Зависание при снятии галочки с животного (комбинированное исправление)

### Проблема
При снятии галочки с животного веб-интерфейс зависал: `selectedProjects` и
`selectedGroups` продолжали содержать ключи снятого животного, `useEffect`
запускал запросы `GET /api/animals/{code}/projects/{project}/groups` для
уже неактуальных проектов, а единственный воркер gunicorn блокировался на
медленном запросе — весь сервер переставал отвечать.

### Изменения

#### 1. `frontend/src/components/JobWizard.tsx` (вариант 1 — корневая причина)
- `toggleAnimal`: при снятии животного удаляются все его ключи из
  `selectedProjects`, `selectedGroups` и `allGroups` (префикс
  `${code}\u0000`). Висящих выбранных проектов/групп больше нет → лишних
  запросов к API нет.

#### 2. `frontend/src/api/client.ts` (вариант 2 — защита от медленных запросов)
- Добавлен `REQUEST_TIMEOUT_MS = 30_000`.
- `request()`: `fetch` с `AbortController`, при срабатывании таймаута —
  `ApiError('Превышено время ожидания запроса (30 с).')`.
- `api.log()`: аналогичный таймаут (использует собственный `fetch`).

#### 3. `Dockerfile` (вариант 3 — параллельность)
- Gunicorn: `--workers 1` → `--workers 2`. Один медленный запрос больше не
  блокирует весь сервер.

### Не изменено
- Бэкенд-логика (`discovery.py`, `job_pipeline.py`, API-контракты).
- Остальные компоненты фронтенда.

### Тесты
Не проводились (по правилу: тесты только по явному указанию пользователя).

## 2026-09-05. Вывод лога job в реальном времени

### Задача
Показывать пользователю лог выполнения пайплайна в реальном времени при
запуске job.

### Текущее состояние (до изменений)
`JobStatus.tsx` уже опрашивал `GET /api/jobs/{id}` и `GET /api/jobs/{id}/log`
каждые 3 секунды и выводил лог в `<pre>`. Бэкенд пишет `log.txt` append-only
на каждом шаге пайплайна (`_append_log` в `job_pipeline.py`), поэтому лог
доступен по мере выполнения.

### Изменения

#### `frontend/src/components/JobStatus.tsx`
- Интервал опроса: 3000 мс → **1500 мс** (`POLL_INTERVAL_MS`) — лог
  обновляется заметно быстрее.
- **Автопрокрутка лога вниз** при обновлении: `logRef` + `stickToBottomRef`;
  если пользователь прокрутил вверх (больше 24 px от низа), автопрокрутка
  не мешает читать.
- **Индикатор «обновляется»** (Chip) рядом со статусом, пока job в статусе
  `queued`/`running`; исчезает в терминальных статусах.
- Визуальное оформление лога: фон `grey.50`, рамка, скругление, отступы,
  `maxHeight` 260 → 320 px.

### Не изменено
- Бэкенд: `log.txt` и `GET /api/jobs/{id}/log` работают как раньше.
- Остальные компоненты фронтенда.

### Тесты
Не проводились (по правилу: тесты только по явному указанию пользователя).

## 2026-09-05. Постоянный журнал выбора «под капотом» в JobWizard

### Задача
Лог должен выводиться постоянно в окне снизу (пользователь должен видеть
«под капотом» выбор животного и групп) ниже кнопки «Запустить пайплайн».

### Изменения

#### `frontend/src/components/JobWizard.tsx`
- Добавлено состояние `logLines: string[]` + `appendLog(line)` (с меткой
  времени `toLocaleTimeString('ru-RU')`, буфер ограничен последними 500
  строками).
- **Окно журнала** добавлено в конец формы, **ниже кнопки «Запустить
  пайплайн»**: `<pre>` с `maxHeight: 240`, автопрокруткой вниз при новых
  строках (`logRef` + `stickToBottomRef`, отключение автопрокрутки, если
  пользователь прокрутил вверх больше чем на 24 px).
- Записи в журнал:
  - `toggleAnimal`: «Выбрано животное: Rb» / «Снято животное: Rb»;
  - `toggleProject`: «Выбран проект: Rb / …» / «Снят проект: …»;
  - `toggleGroup`: «Выбрана группа: … / …» / «Снята группа: …»;
  - `useEffect` загрузки проектов: «Загружаю проекты для: Rb…» →
    «Проекты Rb: N шт. (список)» или «Проекты Rb: не найдены.»;
  - `useEffect` загрузки групп: «Загружаю группы для: Rb / проект…» →
    «Группы Rb / проект: N шт. (список)» или «…не найдены.»;
  - ошибки загрузки проектов/групп также пишутся в журнал.

### Не изменено
- Бэкенд, API-контракты, `JobStatus.tsx` (журнал выполнения job остаётся
  отдельным окном в карточке job).

### Тесты
Не проводились (по правилу: тесты только по явному указанию пользователя).
