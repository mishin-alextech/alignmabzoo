# План модификаций AlignmentViewer для оркестратора ИИ-агентов

Дата согласования: 6 сентября 2026 года.

## 1. Цель, основания и согласованные решения

Внедрять изменения последовательно: косметика → управление отображением → исключения с повторным MSA. Кластеризацию и V(D)J-анализ вынести в подготовительные исследовательские этапы.

Основания: `AGENTS.md`, текущая реализация и `alignmentviewer_ideas.md`. Файл идей является материалом для проектирования, а не самостоятельной операционной инструкцией. Ниже зафиксированы уточнения пользователя и принятые в плане технические решения.

- «Группа» при исключении — папка исходных данных, идентифицируемая животным, проектом и названием группы; это не тип цепи.
- Галочки формируют черновой выбор. Кнопка «Применить исключения и выровнять» запускает Clustal один раз для выбранного набора по явному подтверждению пользователя.
- До успешного завершения остаётся прежнее выравнивание. При ошибке сохраняются результат и черновой выбор.
- Undo/redo возвращают готовые варианты без повторного Clustal.
- Сохраняются существующее разбиение MSA на пакеты и поддержка VHH. Пользователь явно согласовал это исключение из требования переданного `AGENTS.md` об одном общем MSA. Не менять разбиение в рамках данного плана.
- Окно 30/60/120 строк с прокруткой отложено и не входит в текущую реализацию.
- Сортировка CDR3 и ручное перемещение выполняются внутри типа цепи.
- Частота рассчитывается среди оставшихся последовательностей соответствующей панели, исключая gap из знаменателя; строки за пределами видимой области тоже участвуют.
- История интерфейса хранится до закрытия viewer.
- V(D)J-анализ: сейчас подготовить техническое исследование, реализацию планировать по его результатам.
- MMseqs2 — основной кандидат для кластеризации, с высокой вероятностью последующего использования. Окончательные режимы и параметры определить исследованием.
- Для каждого непустого кластера доступно отдельное действие «Выровнять кластер». Оно запускает производную job со всеми участниками кластера, открывает самостоятельный viewer в новой вкладке и не изменяет общий MSA.

Общие ограничения: не писать в `/synced_data/mabzoo`; вычислительные артефакты хранить только в `/app/jobs/<job_id>`; идентификаторы кода английские, UI, документация и ошибки русские. Не добавлять LLM или авторизацию. Тесты не запускать без прямого указания пользователя.

## 2. Разделение идей по сложности

| Идея | Сложность | Содержание |
|---|---|---|
| 1. Уменьшить расстояние между строками | Низкая | Уменьшить вертикальные отступы ячеек вдвое; сохранить размер шрифта |
| 3. «Кластеризовать»: страница-заглушка | Низкая | Страница «Будет доступно позже» с возвратом во viewer |
| 8. Окно 30/60/120 | Отложено | Не реализовывать в текущем цикле |
| 5. Сортировка по длине CDR3 | Средняя | Выбранная схема, отсутствующие аннотации и история порядка |
| 6. Частота аминокислоты | Средняя | Статистика столбцов и дополнительная последняя строка подсказки |
| 9. Ctrl+↑ / Ctrl+↓ | Средняя | Перемещение выбранной строки, управление фокусом, undo/redo |
| 2. Исключение исходной группы | Высокая | Передача происхождения строк, черновой выбор, серверный пересчёт |
| 2а. Исключение клона и undo/redo | Высокая | Стабильные ID, варианты результатов, восстановление состава и порядка |
| 4. Кластеризация и повторное MSA | Исследовательская | MMseqs2, критерии кластеризации и интеграция с Clustal Omega |
| 4а. Отдельное MSA кластера | Исследовательская | Все участники кластера, отдельные координаты и viewer в новой вкладке |
| 7. Аналог IMGT/V-QUEST | Очень высокая | Нуклеотидные входы, базы V/D/J, новый анализ и сопоставление координат |

Название «Исключить клон» в первой реализации относится к отдельной строке viewer. Автоматически связывать тяжёлую и лёгкую цепи по имени нельзя.

## 3. Инструменты и зависимости

### 3.1. Интерфейс

Для косметики и управления отображением достаточно установленных React 18, TypeScript, MUI и Vite. Использовать React reducer для истории, существующую маршрутизацию через query-параметры и MUI `SvgIcon` для стрелок. Новые фреймворки, плагины и браузерные надстройки не нужны.

### 3.2. Исключения и повторное выравнивание

Использовать существующие FastAPI, Pydantic, файловый реестр, Clustal Omega и модуль сопоставления нумерации с MSA. При неизменной белковой последовательности повторный ANARCI не нужен: переиспользовать сохранённую нумерацию.

Удаление пустых столбцов не меняет номера IMGT/Kabat/Chothia, но требует общей проекции `seq`, `numbering` и индексов `cdr` на отображаемые столбцы. После нового Clustal повторно сопоставлять аннотации с новым MSA; не оставлять индексы от старого выравнивания.

### 3.3. Средства проверки

Node.js/npm, Python 3.12 и Docker Compose. При реализации выполнять сборку frontend и проверку импортов backend. Тесты, экспериментальные прогоны и проверки сценариев выполнять только по прямому указанию пользователя. Перечисление проверок в этом плане не является разрешением на запуск.

### 3.4. Кластеризация

Основной кандидат — локальный MMseqs2 в Docker. Исследовать `easy-cluster` и `easy-linclust`, начиная оценку с `easy-cluster`. Проверить закрепление версии, совместимость сборки с CPU сервера, потребление памяти и временного диска. Планировать `--threads 1` при общем лимите двух вычислительных job.

MMseqs2 определяет принадлежность к кластерам; Clustal Omega сохраняется для множественного выравнивания. Не заменять все последовательности представителями кластеров. Сравнить подход с guide tree Clustal как альтернативой упорядочивания, не считать guide tree готовой биологической кластеризацией.

Оба режима MMseqs2 описаны в [официальном репозитории](https://github.com/soedinglab/MMseqs2); параметры идентичности, покрытия и кластеризации — в [руководстве](https://github.com/soedinglab/MMseqs2/wiki). Особенности guide tree Clustal описаны в [документации EMBL-EBI](https://www.ebi.ac.uk/jdispatcher/docs/faqs/clustal/).

До завершения исследования не устанавливать новые зависимости и не фиксировать произвольные биологические пороги.

### 3.5. V(D)J

Основной кандидат исследования — локальный NCBI IgBLAST, `igblastn`, `makeblastdb` и версионированные germline-базы. IMGT/V-QUEST работает с нуклеотидными последовательностями; имеющегося белкового JSON недостаточно для полноценного аналога. Проверить базы и вспомогательные файлы для каждого животного, условия использования и распространения.

Источники: [IMGT/V-QUEST](https://www.imgt.org/IMGT_vquest/user_guide), [установка IgBLAST](https://ncbi.github.io/igblast/cook/How-to-set-up.html), [примеры IgBLAST](https://ncbi.github.io/igblast/cook/examples.html).

## 4. Порядок работы оркестратора

Оркестратор выдаёт каждому агенту контракт по шаблону `AGENTS.md`: разрешённые файлы, входы, выходы, ограничения и критерий готовности. Производственный код делегировать субагентам. Общие файлы изменять последовательно; не выдавать их одновременно нескольким агентам.

После каждой задачи проверить границы изменений, контракт, глобальные ограничения и сборку/импорты соответствующего модуля. Несоответствия возвращать тому же агенту с конкретными замечаниями. Если потребуется файл вне контракта, оркестратор сначала уточняет контракт; агент не расширяет область изменений самостоятельно.

Порядок реализации: **A → B → C → D → E**. Два исследования этапа F могут идти независимо от косметических изменений и параллельно друг другу. Не переходить к реализации кластеризации или V(D)J только на основании наличия исследовательского задания.

## 5. Контракты задач

### Задача A: общая модель состояния viewer

**Этап:** A.

**Файлы для создания/изменения:**

- `frontend/src/components/alignment/viewerState.ts` — создать.
- `frontend/src/components/AlignmentViewer.tsx` — изменить.

**Вход:** текущий `AlignmentResponse` и существующий viewer.

**Выход:** единая модель выбранной строки, порядка, черновых исключений и истории вариантов.

- Исходные данные не мутировать.
- История включает применённый состав, порядок строк и ссылку на готовое MSA.
- Новое действие после undo очищает redo.
- Смена схемы CDR, цветов и размера окна не создаёт запись истории.
- При смене job состояние сбрасывается.
- Сортировка применяется отдельным действием; последующее ручное перемещение не отменяется автоматической пересортировкой.

**Ограничения:** не менять файлы вне списка; не менять API и backend; соблюдать общие ограничения раздела 1; не запускать тесты без указания пользователя.

**Критерий готовности:** существующий viewer работает через общую модель; frontend собирается.

**Выход:**

- Длина CDR3 — число негэповых остатков по индексам выбранной схемы. Отсутствующая аннотация помещается в конец; равные длины сохраняют текущий порядок.
- Статистика рассчитывается на изменение состава или MSA, а не при каждом наведении.

**Ограничения:** не менять файлы вне списка; не устанавливать новые библиотеки; соблюдать общие ограничения; не запускать тесты без указания пользователя.

**Критерий готовности:** поведение одинаково в обычном и полноэкранном viewer; сборка проходит.

### Задача C: происхождение последовательностей

**Этап:** C.

**Файлы для создания/изменения:**

- `backend/app/services/job_pipeline.py` — изменить.
- `backend/app/services/alignment.py` — изменить.
- `frontend/src/api/client.ts` — изменить.

**Вход:** сведения discovery о животном, проекте, группе и исходном файле.

**Выход:** расширенный JSON каждой последовательности:

- `id` — стабильный идентификатор в пределах job.
- `source` — животное, проект, исходная группа и относительный путь файла.

Идентификаторы сохраняются при повторном MSA. Группы с одинаковыми названиями в разных проектах не объединяются. Абсолютные серверные пути клиенту не передаются.

Старые JSON остаются читаемыми. Для них доступно исключение отдельных строк с синтетическими ID; исключение исходных групп недоступно, если происхождение нельзя восстановить однозначно. Не пытаться угадывать исходную группу по имени клона. Способ получения синтетических ID должен совпадать на клиенте и сервере.

**Ограничения:** не менять файлы вне списка; не изменять алгоритмы naming и discovery; соблюдать общие ограничения; не запускать тесты без указания пользователя.

**Критерий готовности:** новые job сохраняют происхождение до viewer; старые результаты открываются; frontend собирается, изменённые backend-модули импортируются.

- Исходную job не перезаписывать; производная содержит всё необходимое для самостоятельного открытия.
- Различать пользовательские исключения и ошибки обработки в отчёте.
- Производные job участвуют в существующих статусах и recovery после перезапуска.

**Ограничения:** не менять файлы вне списка; не запускать повторный ANARCI для неизменных белков; не создавать отдельный конкурирующий лимит вычислений; соблюдать общие ограничения; не запускать тесты без указания пользователя.

**Критерий готовности:** производная job интегрирована в жизненный цикл, recovery и скачивания; исходный результат сохранён; изменённые backend-модули импортируются и frontend собирается. Вычислительную проверку проводить только после прямого разрешения пользователя.

### Задача F1: исследование кластеризации на MMseqs2

**Этап:** F, независимое исследование.

**Файлы для создания/изменения:**

- `docs/alignment_clustering_research.md` — создать.

**Вход:** белковые последовательности, стабильные ID viewer, типы цепей, CDR по трём схемам; основной кандидат MMseqs2; Docker ограничен 2 CPU, максимум две вычислительные job.

**Выход:** проверенное техническое исследование с источниками и рекомендуемым подходом.

- Сравнить `easy-cluster` и `easy-linclust`; начать оценку с `easy-cluster`.
- Исследовать `--min-seq-id`, `-c`, `--cov-mode`, `--cluster-mode`, определение идентичности и фактические гарантии принадлежности к кластеру. Не считать порог гарантией попарного сходства всех участников.
- Отдельно оценить полный вариабельный домен и короткие CDR3; определить ограничения метода на коротких последовательностях.
- Предложить параметры для последующего согласования и экспериментальной проверки, не объявлять их биологически валидированными без данных.
- Проверить закреплённую версию MMseqs2, установку в Docker, совместимость CPU, память, временный диск и `--threads 1`.
- Описать сохранение таблицы «представитель → участники» со стабильными ID, параметрами и версией инструмента в каталоге job.
- Проработать связку MMseqs2 → Clustal Omega → расположение строк блоками кластеров, сохраняя все последовательности и текущее разбиение по типам цепей.
- Разделить два результата: перестановка строк существующего MSA и новый расчёт MSA. Не предполагать, что порядок входного FASTA автоматически обеспечивает соседство кластеров в viewer.
